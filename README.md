# Вычислительная мощность OpenAI и Anthropic

## 1. Постановка и результат

Оценить доступную OpenAI и Anthropic вычислительную мощность и её распределение между инференсом и обучением/исследованиями. 
Учитывается доступная, в том числе арендованная, мощность - это не оценка только собственного оборудования.

| Компания | Нижний сценарий, H100e | Базовый, H100e | Верхний, H100e | Округление для слайда |
|---|---:|---:|---:|---:|
| OpenAI | 2 542 100 | 2 684 950 | 3 012 000 | ≈2,7 млн |
| Anthropic | 1 914 577,27 | 1 968 290,91 | 2 216 104,55 | ≈2,0 млн |

Центральное распределение у обеих компаний: **50% инференс / 50% обучение и исследования**. 
Доля инференса в сценариях — **45–55%**, доля обучения равна `1 − доля инференса`. Это сценарные допущения, а не статистический доверительный интервал и не официальное раскрытие компаний.

При базовой мощности половины составляют 1 342 475 H100e для OpenAI и 984 145,45 H100e для Anthropic.
Значения 1,35 и 1,0 млн получаются при делении уже округлённых итогов слайда; расчёт использует неокруглённые величины.

## 3. Методика по шагам

1. Использовать **H100e**, эквивалент вычислительной мощности NVIDIA H100. Прямое число физических GPU не сопоставимо для неоднородных парков NVIDIA, Trainium и TPU. H100e не гарантирует одинаковую скорость на конкретной нагрузке.
2. Взять базу Epoch AI на конец 2025 года: OpenAI **1 743 000**, Anthropic **1 190 000 H100e**.
3. Для площадок, уже представленных в базе, вычислить прирост: `текущая мощность − мощность на базовую дату`. Для новых доступных площадок использовать соответствующую новую мощность. Это правило исключает повторное добавление уже учтённой базы при принятых исходных данных.
4. Умножить прирост общей площадки на оценочную долю компании и прибавить вклады к базе: `итог = база + Σ(прирост × доля)`.
5. Отдельно распределить итог: `инференс = итог × доля инференса`; `обучение и исследования = итог − инференс`. Изменение распределения не меняет общую мощность.

## 4. Исходные данные и допущения

### OpenAI

Все мощности ниже в H100e. Доли относятся к приросту, а не ко всей площадке.

| Площадка | Конец 2025 | На дату модели | Прирост | Доля: нижняя / базовая / верхняя | Базовый вклад |
|---|---:|---:|---:|---|---:|
| Stargate Abilene | 255 000 | 509 000 | 254 000 | 100% / 100% / 100% | 254 000 |
| CoreWeave Denton | 65 000 | 253 000 | 188 000 | 70% / 80% / 100% | 150 400 |
| Fairwater Atlanta | 388 000 | 769 000 | 381 000 | 50% / 65% / 100% | 247 650 |
| Fairwater Wisconsin | 0 | 446 000 | 446 000 | 50% / 65% / 100% | 289 900 |

`1 743 000 + 254 000 + 150 400 + 247 650 + 289 900 = 2 684 950 H100e`.

80% Denton и 65% Fairwater — допущения исходной модели. Верхние 100% — техническая граница сценария, а не подтверждённая доля OpenAI.

### Anthropic

| Компонент | Базовый расчёт, H100e |
|---|---:|
| База на конец 2025 | 1 190 000 |
| Rainier / New Carlisle | 686 000 − 471 000 = 215 000 |
| Colossus 1 | 276 000 |
| Colossus 2 | (325 000 − 230 000) × (1 112 000 / 440 000) = 240 090,91 |
| Lake Mariner | 59 000 × 80% = 47 200 |
| Итого | 1 968 290,91 |

Для Colossus 2 модель вычитает физические GPU Colossus 1 из общего раскрытого количества и применяет средний коэффициент **2,5273 H100e/GPU**. Он специфичен для этой площадки и не является универсальным коэффициентом GPU. Нижний/верхний сценарии используют множители 85%/115% к полученному вкладу; для Lake Mariner доли равны 50%/80%/100%.

**Оговорка верхнего сценария:** исходная модель добавляет Anthropic ещё **200 000 H100e** возможной дополнительной мощности. Это неподтверждённое сценарное допущение, не установленный ввод в эксплуатацию. Оно сохранено для воспроизводимости исходного Excel, но не включено в базовые ≈2,0 млн. Без этой добавки верхний сценарий равен **2 016 104,55 H100e**. Поэтому верхнюю оценку 2,216 млн нельзя описывать как только подтверждённую введённую мощность.

### Почему 50/50

Исходные материалы ссылаются на примерно равное распределение OpenAI в 2025 году и смешанное назначение новой инфраструктуры. Для Anthropic 50/50 также является аналитическим допущением. Данных о точном текущем распределении в модели нет. Диапазон 45–55% отражает выбранную чувствительность, а не измеренную точность.

## 5. Запуск

Требуется Python 3.10 или новее. Все команды выполняются из корня репозитория.

### Скрипт без установки зависимостей

```bash
python3 src/case_1_gpu_capacity.py
```

В Windows можно использовать `py` вместо `python3`.

### Notebook

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m jupyterlab notebooks/case_1_gpu_capacity.ipynb
```

В Windows PowerShell активация: `.venv\Scripts\Activate.ps1`. В Jupyter выбрать **Restart Kernel and Run All Cells**. Notebook самодостаточен: не требует подключения Excel, сети или абсолютных путей к исходным файлам. Сеть нужна только для первоначальной установки Jupyter.

## 6. Как менять предположения

В `src/case_1_gpu_capacity.py` измените доли в `openai_sites`, параметры компонентов Anthropic или `INFERENCE_LOW/BASE/HIGH`. Запустите скрипт повторно. Чтобы сохранить синхронизацию, перенесите обновлённый текст скрипта целиком в кодовую ячейку Notebook и выполните её заново. Excel является отдельной моделью и автоматически из Python не обновляется.
